# 内容同步管道设计 · 飞书 → 官网

- 版本: v1.0(设计评审中,未实施)
- 日期: 2026-09-16
- 范围: 飞书多维表格作为内容登记与发布开关;Blog 与 Publications **各自独立一张表**,字段分别设计
- 关联: docs/design/hero.md(站点设计)

---

## 0. 核心原则

1. **表 = 发布开关**。不在表里的内容,永远不会出现在网站上。
2. **一个栏目一张表**。Blog 与 Publications 字段不同、机制不同(见 §4),不合并。
3. **文件夹只管人类浏览**。文档放在知识库哪个目录,只影响你自己找东西;发不发由表的"状态"决定。
4. **能自动的不人工**。标题、摘要、slug、发布链接由脚本回填;人只填"文档链接 + 状态(+标签)"。

## 2. Blog 登记表

**内容在哪**:正文在飞书文档里,表只存元数据和发布状态。

| 字段 | 类型 | 谁填 | 说明 |
|---|---|---|---|
| ID | 自动编号 | 系统 | NO.001 起 |
| 标题 | 文本(主字段) | **脚本镜像** | 每次发布/探测时镜像文档标题,**纯展示**,不改数据流向 |
| 文档 | 文本 | **用户/脚本** | 飞书文档链接;`new` 命令自动生成 |
| 状态 | 单选 | 用户+脚本 | **draft / pending / published / updated** |
| 标签 | 多选 | 用户(可选) | 网站分类标签 |
| 发布日期 | 日期 | 脚本回填 | 空则取首次发布当天并**钉死**,不漂移 |
| 已发布链接 | 文本 | 脚本回填 | 网站 URL |
| 文件名 | 文本 | **脚本控制** | slug(网址名),**隐藏于"同步状态"视图**;首次发布生成后永久固定 |
| 已同步版本 | 文本 | 脚本回填 | 上次发布时的 revision_id,**隐藏于"同步状态"视图** |

**视图**:主视图(标题/ID/文档/状态/标签/发布日期/已发布链接,7 列)+ 同步状态(内部字段)

**元数据在文档里,不在表里**(v1.4):标题 = 文档标题;作者、摘要写在文档顶部的**引用块元信息模板**中:

```
> 作者: Fan Zhang
> 摘要: (可留空,留空则自动取正文首段)
```

### 建档流程(`new` 命令)

```bash
node scripts/sync.mts new "Article title"
```

复制模板文档到 OEM Blog 文件夹 → 在 Blog 表建一行(标题镜像 + 文档链接 + 状态 draft)→ 你点开链接写正文 → 状态切 pending → 同步发布。

**状态机(v1.3,手动发布闸门,取值英文)**:

```
                 (用户手动选)                (同步发布)
  draft ────────────→ pending ────────────→ published
   ↑                     ↑                       │
   │ (用户选,下架)        │ (用户复核后手动选)      │ (同步探测到 revision 变化)
   └─────────────────────┤                       ↓
                         └─────────────────  updated
```

- **pending 是唯一的发布触发器,只能由人手动设置**,同步绝不自动设置
- published 的文章在飞书里被修改 → 同步只把它翻成 updated(看板可见),**不改动网站**
- 人工复核后选回 pending → 下次同步重新发布,并刷新"已同步版本"
- 探测用轻量调用(只拉文档目录拿 revision_id,毫秒级),版本相同则连正文都不拉

## 3. Publications 论文表

**内容在哪**:数据本身就是内容(没有飞书文档),这张表既是网站数据源,也是组内的论文台账。

| 字段 | 类型 | 谁填 | 说明 |
|---|---|---|---|
| 标题 | 文本 | **用户** | 论文题目 |
| 作者 | 文本 | **用户** | 完整作者列表,按署名顺序 |
| 状态 | 单选 | **用户** | 筹备中 / 已投稿 / 已接收 / 已发表 |
| 上网站 | 复选框 | **用户** | 勾选 = 同步到网站 |
| 期刊/会议 | 文本 | 用户 | 如 Atmospheric Chemistry and Physics |
| 年份 | 数字 | 用户 | 2026 |
| 组内作者 | 人员(多选) | 用户(可选) | 组内参与人,便于统计产出 |
| 卷期页码 | 文本 | 用户(可选) | |
| DOI | 文本 | 用户(可选) | 10.xxxx/… |
| 链接 | 文本 | 用户(可选) | 出版商 / arXiv / PDF 外部链接 |
| PDF | 附件 | 用户(可选) | 论文 PDF 归档(仅组内存档,**不上网站**) |
| 标签 | 多选 | 用户(可选) | 主题标签 |

**视图**:表格(按年份分组,主视图)+ 看板(按状态,追踪投稿进度)

**上网站规则**:只有勾选了"上网站"的行进入网站;论文状态不影响展示(筹备中的论文若勾选,会以"in preparation"出现)。由用户决定什么对外可见。

## 4. 同步机制(两张表机制不同,是本质差异)

### Blog:文档 → Markdown 文章

```
扫表
  ├─ draft/空   → 删除站上对应文章(下架)
  ├─ updated    → 跳过,等人工复核
  ├─ published  → 轻量探测 revision_id(docs +fetch --scope outline,bot 身份)
  │     ├─ 与"已同步版本"相同 → 跳过(不拉正文)
  │     └─ 不同 → 状态翻 updated,顺带镜像最新标题,不碰网站
  └─ pending    → 拉文档(docs +fetch --doc-format markdown,bot 身份)
        → 解析:标题=文档 H1;作者/摘要=顶部引用块元信息;正文=其余
        → 图片下载到 public/images/blog/(先清旧图),图链替换为本地路径
        → 生成 src/content/blog/<文件名>.md(含 frontmatter)
        → git commit + push → GitHub Actions 自动构建上线
        → 回写(user 身份):状态=published、标题镜像、已同步版本、
          文件名(空则生成)、发布日期钉定、已发布链接
```

### Publications:表 → 数据文件

```
扫表(上网站 = true)
  → 生成 src/data/publications.json(标题/作者/状态/期刊/年份/卷期/DOI/链接/标签)
  → git commit + push
  → 网站 publications 页面读取该文件,按年份分组渲染
```

Publications 不经过 Markdown,因为它是**结构化数据**不是长文;页面代码(届时重做)直接消费 JSON。

## 7. 建设顺序

1. 补权限:我给后台链接 → 你开通 bitable scopes
2. 建表:以**你本人身份**建两张表 + 字段 + 视图(如需要,先做一次 base 域授权)
3. 验证:bot 身份读表、写回各测一次
4. 写 `scripts/sync.mjs`
5. 全链路测试:你在 Blog 表加一行测试文章 → 同步 → 网站出现 → 状态自动变已发布
