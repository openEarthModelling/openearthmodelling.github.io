# 内容同步管道设计 · 飞书 → 官网

- 版本: v1.0(设计评审中,未实施)
- 日期: 2026-09-16
- 范围: 飞书多维表格作为内容登记与发布开关;Blog 与 Publications **各自独立一张表**,字段分别设计
- 关联: docs/design/hero.md(站点设计)

---

## 0. 核心原则

1. **表 = 发布开关**。不在表里的内容,永远不会出现在网站上。
2. **一个栏目一张表**。Blog 与 Publications 字段不同、机制不同(见 §4),不合并。
3. **文件夹只管人类浏览**。文档放在知识库哪个目录,只影响你自己找东西;发不发由表的"状态"决定。
4. **能自动的不人工**。标题、摘要、slug、发布链接由脚本回填;人只填"文档链接 + 状态(+标签)"。

## 1. 知识库最终形态

```
OEM Website/(知识库, space_id 7686102458560433448)
├── Blog/                   ← 博客文档写在这里(人类目录)
├── Projects/               ← 未来项目内容
├── Publications/           ← 预留(论文数据主要在表里,此目录可空置或放归档 PDF)
├── 📊 Blog 登记表           ← 多维表格(新)
└── 📊 Publications 论文表   ← 多维表格(新)
```

两张表都建成**知识库内的节点**,应用作为空间成员自动获得访问权,无需逐表授权。

## 2. Blog 登记表

**内容在哪**:正文在飞书文档里,表只存元数据和发布状态。

| 字段 | 类型 | 谁填 | 说明 |
|---|---|---|---|
| 标题 | 文本 | **脚本回填** | 取文档标题(表里已有值则不覆盖) |
| 文档 | 文本 | **用户** | 粘贴飞书文档链接(必填) |
| 状态 | 单选 | **用户** | 草稿 / 待发布 / 已发布 |
| 标签 | 多选 | 用户(可选) | 网站上的分类标签,如 气溶胶 / 海洋 / 教程 |
| 作者 | 文本 | 脚本回填 | 空则默认 Fan Zhang |
| 摘要 | 文本 | 脚本回填 | 空则取正文首段前 ~140 字(表里已有值则不覆盖) |
| 文件名 | 文本 | 脚本回填 | slug,首次同步生成后**永久固定**,保证 URL 稳定 |
| 发布日期 | 日期 | 用户(可选) | 空则取首次同步当天 |
| 已发布链接 | 文本 | 脚本回填 | 网站 URL,点开即看 |
| 创建时间 | 自动 | 系统 | 行创建时间 |

**视图**:看板(按状态,日常工作台)+ 表格(全量)

**状态机**:

```
草稿 ──→ 待发布 ──→ 已发布
 ↑                    │
 └──── 改回草稿 = 网站下架(脚本删除对应文章)
```

- 脚本处理 `待发布` 和 `已发布` 两类:前者首次发布,后者用于**文档改动后的更新**
- 已发布的文章改了文档 → 说一声同步 → 网站更新(内容无变化则不产生提交)

## 3. Publications 论文表

**内容在哪**:数据本身就是内容(没有飞书文档),这张表既是网站数据源,也是组内的论文台账。

| 字段 | 类型 | 谁填 | 说明 |
|---|---|---|---|
| 标题 | 文本 | **用户** | 论文题目 |
| 作者 | 文本 | **用户** | 完整作者列表,按署名顺序 |
| 状态 | 单选 | **用户** | 筹备中 / 已投稿 / 已接收 / 已发表 |
| 上网站 | 复选框 | **用户** | 勾选 = 同步到网站 |
| 期刊/会议 | 文本 | 用户 | 如 Atmospheric Chemistry and Physics |
| 年份 | 数字 | 用户 | 2026 |
| 组内作者 | 人员(多选) | 用户(可选) | 组内参与人,便于统计产出 |
| 卷期页码 | 文本 | 用户(可选) | |
| DOI | 文本 | 用户(可选) | 10.xxxx/… |
| 链接 | 文本 | 用户(可选) | 出版商 / arXiv / PDF 外部链接 |
| PDF | 附件 | 用户(可选) | 论文 PDF 归档(仅组内存档,**不上网站**) |
| 标签 | 多选 | 用户(可选) | 主题标签 |

**视图**:表格(按年份分组,主视图)+ 看板(按状态,追踪投稿进度)

**上网站规则**:只有勾选了"上网站"的行进入网站;论文状态不影响展示(筹备中的论文若勾选,会以"in preparation"出现)。由用户决定什么对外可见。

## 4. 同步机制(两张表机制不同,是本质差异)

### Blog:文档 → Markdown 文章

```
扫表(状态 ∈ {待发布, 已发布})
  → 按"文档"字段拉取飞书文档(docs +fetch --doc-format markdown)
  → 文档内图片下载到 public/images/blog/,正文里的图链替换为本地路径
  → 生成 src/content/blog/<文件名>.md(含 frontmatter)
  → git commit + push → GitHub Actions 自动构建上线
  → 回写:状态=已发布、已发布链接、标题/摘要/文件名(空字段才填)
```

### Publications:表 → 数据文件

```
扫表(上网站 = true)
  → 生成 src/data/publications.json(标题/作者/状态/期刊/年份/卷期/DOI/链接/标签)
  → git commit + push
  → 网站 publications 页面读取该文件,按年份分组渲染
```

Publications 不经过 Markdown,因为它是**结构化数据**不是长文;页面代码(届时重做)直接消费 JSON。

## 6. 权限与安全(v1.1 实测更新)

| 项 | 状态 |
|---|---|
| 应用 scopes:wiki 全套 | ✅ 已开通 |
| 应用 scopes:base 系列(读表/读记录) | ✅ 已开通,bot 可读两张表 |
| bot 回写表格 | ❌ 被拒(知识库成员 API 仅 admin/member 两档,member 对表格只读) |
| 用户身份:读写表格 | ✅ 全通 |
| **同步脚本运行身份 = 用户身份** | ✅ **决策(2026-09-16)** |
| App Secret | 从未进入仓库;存于本机 lark-cli 配置 |

**身份决策说明**:脚本以用户身份运行,理由:①当前工作流为"用户说一声→同步",非无人值守场景;②用户身份读写全通,零额外授权;③符合用户"以我的名义操作"的要求。将来若做 CI 定时同步,再为 bot 升级空间权限(需用户操作:空间成员管理里把应用改为管理员,或补 docs 域授权后按文档级协作者授权)。

---

## 7. 建设顺序

1. 补权限:我给后台链接 → 你开通 bitable scopes
2. 建表:以**你本人身份**建两张表 + 字段 + 视图(如需要,先做一次 base 域授权)
3. 验证:bot 身份读表、写回各测一次
4. 写 `scripts/sync.mjs`
5. 全链路测试:你在 Blog 表加一行测试文章 → 同步 → 网站出现 → 状态自动变已发布

## 8. 未来扩展(不在本次范围)

- **Projects 页**:不建议用表维护——仓库信息的事实源就是 GitHub,建议构建时从 GitHub API 拉取
- **CI 自动同步**:把同步放进 GitHub Actions 定时跑(需要把应用凭据存为仓库 Secrets,涉及密钥托管,届时再评估)
- **论文 PDF 公开托管**:如需要,加"PDF 是否公开"字段,脚本把附件同步到 public/pdfs/
- **表单投稿**:Base 表单视图可让组员提交文章信息(多作者时)
